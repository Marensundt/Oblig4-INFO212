# Data-validation rules derived from the historical order data

Source: `EkteMat_project_inbox/orders_2024_2025_export.xlsx`, sheet 1 (820 data rows, 16 columns), analysed 2026-10-28 with a read-only Python script (standard library only; the source file was not modified). Row IDs are `order_id` values. Sheet 2 note: "Kitchen capacity: ~400 covers/day; ~250 if a served wedding dinner is on the same day."

> **Status: ASSUMPTION — proposed by the team, not official Oblig 4 requirements.** Oblig 4 does not specify validation rules. The only rules that coincide with the official text are the allowed values of order status (DV-07) and payment status (DV-08), which come from OB4 A3, and the minimum-order check, which comes from OB4 C2. **DV-02 (400-guest threshold) is optional and not mandatory.** All rules are to be confirmed by the team/product owner before implementation.

## Decision (2026-10-28, OPEN-10 — `docs/plans/03-phase1-model-and-repositories.md` §2)

| Group | Rules | Status |
|---|---|---|
| **Official (Oblig 4)** | DV-07 order status values (A3); DV-08 payment status values, default *not paid* (A3); minimum order quantity ≥ 1 per item (needed for C2) | Implemented in phase 1 (enums + schema) |
| **Essential integrity (ASSUMPTION)** | DV-01 guests ≥ 1, guest-group count ≥ 1, line quantity ≥ 1; DV-03 price > 0; DV-05 computed totals; DV-06 unique generated order number; DV-09 fixed lists; DV-12 separate guest-group fields without names | Implemented in phase 1 (schema / design) |
| **Form rules (ASSUMPTION)** | Quantity ≥ item minimum in cart (OFFICIAL C2, phase 5); DV-10 ≥ 1 category per item (phase 3); DV-04 event date in the future, DV-11 ≥ 1 guest group and counts ≤ guests (phase 6) | Built with their forms |

## Proposed rules (analysis)

Each problem in the old Excel process becomes a proposed rule the new system enforces — as an **acceptance criterion** (checked in the form/model) and as a **database constraint** (SQLite now; the same rule must hold in the Neo4j repositories later).

| ID | Problem found | Count | Example rows | Rule in Ekte Mat Online | Acceptance criterion | DB constraint (SQLite) | Story |
|---|---|---|---|---|---|---|---|
| DV-01 | Guest count zero or negative | 3 | 24-0024, 25-0624, 25-0382 | Number of guests is an integer ≥ 1 | Given guests < 1, when the order is submitted, then it is rejected | `CHECK (guest_count >= 1)` on `orders`; `CHECK (count >= 1)` on `guest_groups` | US-12, US-13 |
| DV-02 | Implausible guest count (5 000; all other orders ≤ 159) | 1 | 24-0314 | **Optional, not mandatory (ASSUMPTION):** guests above the daily capacity (400, from the data pack, not from Oblig 4) need confirmation — warning, not block (CF-07); belongs with optional US-24 | Given guests > 400, when the order is submitted, then the customer must confirm the number | — (application rule) | US-12, US-24 |
| DV-03 | Price per guest = 0 | 2 | 24-0187, 25-0380 | Food item price is an integer > 0 NOK *(ASSUMPTION: free items not allowed)* | Given price ≤ 0, when an admin saves an item, then it is rejected | `CHECK (price_nok > 0)` on `food_items` | US-01 |
| DV-04 | Event date before order date | 4 | 24-0265, 25-0384, 25-0556, 25-0608 | Event date must be after the submission date | Given an event date today or earlier, when the order is submitted, then it is rejected | — (depends on "today"; application rule) | US-12 |
| DV-05 | Total ≠ guests × price per guest | 12 | 24-0024, 24-0102, 24-0155, 24-0247 … | Totals are always **computed**, never typed in | Given order lines, when the order is shown, then total = Σ(quantity × unit price) | No `total` column stored; unit price snapshot on `order_lines` with `CHECK (unit_price_nok > 0)`, `CHECK (quantity >= 1)` | US-09, US-12 |
| DV-06 | Duplicate order IDs (exact duplicate rows) | 5 | 24-0014, 24-0026, 24-0133, 25-0793, 25-0800 | Order numbers are generated by the system and unique | Given two orders submitted at the same time, when they are stored, then they get different order numbers | `UNIQUE (order_number)`; `PRIMARY KEY` generated | US-12 |
| DV-07 | Order status misspelled ("Confimed") | 3 | 24-0034, 25-0583, 25-0653 | Order status is one of the official values (A3) | Given a status outside the list, when it is saved, then it is rejected | `CHECK (status IN ('submitted','approved','in_preparation','delivered','rejected','cancelled'))` | US-15 |
| DV-08 | Payment status not tracked at all | 820 | (no column) | Every order has a payment status, default *not paid* | Given a new order, then payment status = not paid | `payment_status NOT NULL DEFAULT 'not_paid'` + `CHECK (… IN ('not_paid','deposit_paid','invoiced','paid'))` | US-16 |
| DV-09 | Channel spelled 6 different ways (E-post, email , EMAIL, e-mail, Phone call, phone) | 6 | 24-0022, 24-0159, 24-0275, 24-0336, 24-0294, 25-0568 | Free-text categories are replaced by fixed lists (event categories, allergens, dietary labels) | Given the item form, then categories, allergens and labels are chosen from lists, not typed | Lookup tables / `CHECK` lists for allergens and labels; FK to `event_categories` | US-01 |
| DV-10 | Missing customer type / event kind | 8 | 24-0108, 24-0261, 24-0256, 25-0415 … | Every food item has ≥ 1 event category; every order belongs to a registered customer | Given no category, when an item is saved, then it is rejected (US-01 AC3) | `customer_id NOT NULL REFERENCES users(id)`; ≥ 1 category checked in model | US-01, US-12 |
| DV-11 | Empty dietary notes — "none" cannot be told apart from "not asked" | 234 | 24-0199, 24-0158, 24-0003 … | Each order has ≥ 1 guest group; allergies chosen from a list; "no allergies" is an explicit choice *(ASSUMPTION)* | Given an order without guest groups, when submitted, then it is rejected | `guest_groups.order_id NOT NULL REFERENCES orders(id)`; ≥ 1 group checked in model | US-13 |
| DV-12 | Free-text dietary notes ("nut allergy x1", "vegan x4") mix allergy, diet and count | all | — | Allergies (list), dietary notes (text) and count are separate fields per guest group; no guest names | Given a guest group, then label, count, allergies and notes are separate fields | `guest_group_allergens(group_id, allergen)` with `CHECK` list | US-13 |

**Row counts:** 820 rows read; 5 rows are exact duplicates (815 unique orders). No rows were removed from the source file — this analysis only reports problems.
